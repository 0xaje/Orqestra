# ORQ-002 — Transaction schema and safe execution gate

ORQ-001 established that native utility.batchAll, assets, balances and contracts calls exist on runtime specVersion 3002. This does **not** prove permissions, deposits, fee affordability, successful execution or rollback.

## Before signing
1. Inspect metadata argument types using `npx tsx src/inspect.ts`.
2. Obtain a funded **testnet-only** SS58 account. Never paste its mnemonic/private key into chat or commit it.
3. Choose a unique asset ID, verify it is unoccupied, and estimate deposit and fees from current chain storage/constants.
4. Compile only allowlisted calls with runtime version and argument validation.
5. Dry-run if a supported chain API is available; otherwise disclose the limitation.
6. Obtain explicit wallet approval and submit the signed extrinsic.
7. Verify inclusion/finality, events, asset storage, and balances; do not treat dispatch inclusion as success.
8. Run a deliberate failing atomic batch and verify no earlier state changes persisted.

## Security constraints
- No private keys in source, logs or browser local storage.
- Do not claim EVM atomicity; EVM and native RPC are separate interfaces.
- Reject runtime upgrades until call metadata is revalidated.
- Always distinguish failed dispatch from RPC timeout and uncertain finality.

## Current status
Metadata inspection utility committed. Transaction submission and rollback evidence **not yet implemented**.
